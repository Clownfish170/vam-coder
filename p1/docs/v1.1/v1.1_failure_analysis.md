- **Episode Success Rate = 同一 (task, baseline, rep) 下 step1 与 step2 均 eval_success=1**；

## 5. 失败原因归类（带证据）

### 5.1 【主因·架构】对话可见性与 `history_sent` 不一致 → 不安全省略

**机制（F8，代码事实）**：

1. `run_p1.py` 仅在历史中追加 **assistant** 响应：`history.append({"role":"assistant", ...})`（约 L487）；**上一轮 user 上下文（含 FILE 源码）不会进入后续 messages**。
2. `assemble_vam_coder` 用 `history_sent[symbol_id]==source_hash` 判断“对话中已有相同哈希内容”后省略（`p1_common.py` L433–461）。
3. `history_sent` 在文件被 **写入当前 context** 时更新（L486–489），记录的是“曾在某次 user 上下文中发送过”，**不是**“仍在当前可见 messages 中”。
4. 因此：上一步若 assistant 为 `NO_EDIT` 或未回写完整文件，下一步 REUSE_KV 仍可能省略，而模型实际 **看不到** 该源码。

**定量证据（vam step2，formal 全量）**：

| 可见 FILE 块数（assistant 历史 + 当前 context） | n | episode 步成功率 | NO_EDIT 率 |
| --- | --- | --- | --- |
| ≤1 | 8 | **0%** | **100%** |
| 2 | 28 | 25% | 50% |
| ≥3 | 48 | ~58–100% | 0% |

空 context（ctx=0 且 hist_FILE=0）：8 个 step2，**全部 reuse_omitted>0，全部失败**。  
代表任务：`v1_RUR02`、`v1_RUR03`、`v1_DEL01` step2。

RUR02 step2 messages（证据）：

```
system
assistant NO_EDIT          # step1 响应
user  [MODE]+TASK，无 FILE   # 当前步；hot/stable 源码已 REUSE_KV 省略
```

模型对“hot() 返回 3”输出 `NO_EDIT`；memory_off 同任务同结构输入源码则通过。

**判定：VAM-Coder 在 1.5B 上的主要失败路径。**  
这是双层思想下的 **寻址/注入安全** 问题，不是“放弃符号记忆”的理由——修复应是省略前校验 **真实可见 messages**，而非取消符号层。

### 5.2 【次因·模型】协议不遵循 / 错误编辑（与记忆路由无关或被路由放大）

| 证据 | 说明 |
| --- | --- |
| RUR02 **step1** | context 含 hot/stable **全部源码**，与 memory_off 同构；vam 仍 `NO_EDIT`（seed=0 下仍失败）→ 模型/提示词敏感 |
| STM02 step2 | vam 已 EXPAND bill.py+fee.py 完整源码；模型 `due_fast=6*qty` 漏 `+1`；memory_off 同源码正确 |
| RFS01 step1 | 两侧均有 mode/app 全源；vam 将 mode.py 改成仅 docstring（删掉 describe）→ step2 级联 ImportError |
| 10 机制任务 | 资格+正式双复现的模型违例名单一致 |

**F9**：即使注入完整正确源码，1.5B 仍会在部分任务上违反编辑协议。  
**H2**：MODE 长说明行（vam 恒比 memory_off 多约 +23 prompt tokens 的路由元话语）可能扰动 1.5B 行为（RFS01 等），属 **H**，需 V1.1 消融验证。

### 5.3 【次因·级联】失败步之后的 DROP/清空放大错误

- RFS01 step1 模型删掉 `describe` 后，step2 决策对 mode.py 为 tombstoned/DROP，上下文几乎清空 → 持续失败。
- DEL01 step2：`lib.py::dead` tombstoned → DROP；`app.py` REUSE_KV 省略 → 空上下文 → `NO_EDIT`。

**F10**：一次错误编辑 + “符号失效即从上下文消失”会把可恢复错误变成不可恢复。

### 5.4 【成本】记忆管理开销抵消省略收益

- 每步固定 MODE 路由说明 + 逐符号决策文本；step1 平均 +27.5 tokens vs memory_off。
- REUSE_KV 省略仅在 hash 命中时发生，且 **未**补偿“模型因缺上下文失败”后的无效步。
- episode 全成功成本：vam 2160 vs memory_off 1204（Block A）。

**F11**：当前 V1.0 **没有** 净效率收益；收益统计必须包含检索/装配/回退/失败步，而非只统计 omitted_est。

### 5.5 【排除或弱支持】

| 假设 | 判定 | 依据 |
| --- | --- | --- |
| 模型不遵循符号协议 | **部分支持（H/F 混合）** | 10 任务违例；NO_EDIT；错误 FILE；但非全部失败 |
| 检索失败（ID 错/未命中） | **弱** | 决策 symbol_id 与任务文件一致；未见 ID 空洞；失败更多在“省略了正确 ID 的内容” |
| 记忆内容过期/依赖缺失 | **弱–中** | stale/unverified 会强制 EXPAND（正确）；过期导致的问题被 EXPAND 缓解；tombstone DROP 过激 |
| 依赖解析错误 | **弱** | 依赖闭包失效路径存在且触发（如 CLS/CFD）；主失败不在解析表错误 |
| 注入过多或不足 | **充分支持（主因）** | 不足：空 context+NO_EDIT；过多：MODE/决策话术开销；summary 类则信息丢失更严重 |
| 管理开销抵消效率 | **充分支持** | F4/F11 |

## 6. 结论（阶段一）

1. **正式数据可支持诊断**；不得据此宣称架构有效或无效（单模型、无 CI）。
2. V1.0 vam_coder 的核心工程缺陷是：**用“曾发送哈希”替代“当前 messages 可见内容”做安全省略**，在 assistant-only 历史下制造系统性“模型盲区”。
3. 1.5B 模型协议能力有限，会放大盲区与错误编辑；V1.1 必须在 **注入安全** 与 **协议极简** 上改进，而不是堆更多元话语。
4. 效率上 V1.0 未建立优势；V1.1 必须以 **Total Tokens per Successful Episode** 与完整开销账本联合评价。

→ 进入阶段二：在保留双层 Token（内部静态表示 + 外部符号寻址）前提下，设计 V1.1 最小可行改进。
