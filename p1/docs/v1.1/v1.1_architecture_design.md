# VAM-Coder V1.1 架构设计（阶段二）

状态：**设计稿（最小可行改进）**。实现前须与阶段三文件清单一并评审。  
约束：不推翻双层 Token；冻结 P0 / v0.2 / P1-v1.0 资产只读；新旧架构可切换。

依据：`p1/docs/v1.1_failure_analysis.md`。

## 0. 设计目标与非目标

### 目标

在保留：

1. **内部静态可复用表示**（L0：符号索引 / 内容哈希 / 依赖闭包 / 有效性）  
2. **外部符号 ID 寻址记忆**（L1 元数据索引 + L2 按需完整内容）  
3. **静态表示与动态记忆分离**  
4. **通过符号寻址减少重复上下文**

的前提下，修复 V1.0 的主失败路径，并建立可审计的成本账本。

### 非目标（本版不做）

- 真实张量级 KV 仓 / 跨请求 GPU 缓存管理  
- 训练模型或更换主模型（仍优先 Qwen2.5-Coder-1.5B-Instruct Q6_K）  
- 硬编码任务答案、删除任务必需信息  
- 直接启动完整正式实验

## 1. 问题 → 设计映射

| V1.0 问题（诊断） | V1.1 机制 |
| --- | --- |
| `history_sent`≠当前 messages 可见内容 → 不安全 REUSE_KV | **可见性证明（Visibility Proof）**：省略前校验 assistant 历史中完整 FILE 内容 |
| 无“本步是否需要检索”决策 | **外部记忆控制器（EMC）** |
| tombstone 即 DROP，清空仍需编辑的文件 | **文件级保留策略** + 符号失效≠文件消失 |
| 缺元数据 version/type/dependencies/source | **MemoryRecord v1.1** |
| 无失败回退 | **Fallback：EXPAND → 必要时全文件读入；无法确认则诚实报不足** |
| 注入前后无审计 | **Injection Audit Log** |
| 成本只记 omitted_est | **成本账本 CostLedger**（检索/索引/注入/回退） |

## 2. 分层记忆（L0 / L1 / L2）

```text
┌─────────────────────────────────────────────────────────┐
│ L0 内部静态可复用表示（不进模型上下文，除非映射为 L1/L2）   │
│  · 符号表 symbol_id → file, qualname, kind              │
│  · content_hash, version, type                          │
│  · dependencies（provider→caller）                      │
│  · validity ∈ {valid, stale, unverified, tombstoned}    │
│  · source（workspace path / edit id）                   │
└───────────────────────────┬─────────────────────────────┘
                            │ 索引投影（极轻）
┌───────────────────────────▼─────────────────────────────┐
│ L1 外部记忆索引 / 轻量元数据（可选注入，默认 0~数十 token） │
│  · 一行一条：id | file | type | ver | hash8 | validity  │
│  · 仅当 EMC 选择“展示目录”时注入；禁止整表灌入             │
└───────────────────────────┬─────────────────────────────┘
                            │ 按需物化
┌───────────────────────────▼─────────────────────────────┐
│ L2 完整记忆内容（按文件读当前源码 / 按需摘要）              │
│  · EXPAND：workspace 当前全文件（真源码）                 │
│  · COMPRESS：仅当摘要可证明不替代源码编辑所需信息时         │
│  · 本任务集默认：需要编辑/计算的文件 → 必须 L2 源码        │
└─────────────────────────────────────────────────────────┘
```

**分级铁律**：L1/L2 的引入必须降低 **Total Tokens per Successful Episode**，而不是增加“看起来像记忆”的说明文字。L1 默认关闭整表注入。

### 2.1 MemoryRecord v1.1

```json
{
  "symbol_id": "v1_RUR02:hot.py::hot",
  "file_path": "hot.py",
  "qualified_name": "hot",
  "type": "function",
  "content_hash": "…",
  "version": 3,
  "dependencies": ["stable_a.py::fa"],
  "dependents": [],
  "source": {"kind": "workspace", "path": "hot.py", "edit_id": null},
  "validity": "valid",
  "updated_at": "…",
  "prev_versions": [{"version": 2, "content_hash": "…"}]
}
```

- **静态表示（L0）**：结构与哈希。  
- **动态记忆（外层）**：version 递增、validity 迁移、tombstone、依赖闭包重算；全部写 **Mutation Log**。  
- 与 L0 的边界：L0 索引对象只读投影；动态更新通过 `update_entry()` 事务，禁止散落写库。

## 3. 模块设计

```text
                    ┌──────────────────┐
   step task ──────►│ MemoryController │  EMC
                    │  (route? ids?)   │
                    └────────┬─────────┘
                             │ RetrievePlan{need, ids[], mode}
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        Visibility      Validator       Assembler
        Tracker         (hash/ver/dep)  (L1/L2 注入)
              │              │              │
              └──────────────┴──────┬───────┘
                                    ▼
                            InjectionAudit
                                    │
                                    ▼
                              Model call
                                    │
                                    ▼
                            CostLedger + MutationLog
```

### 3.1 外部记忆控制器（EMC）

**输入**：当前 step 指令、工作区文件列表、L0 索引、可见性状态、预算。  
**输出**：`RetrievePlan`。

规则（可解释、可单测，本版不用 LLM 路由）：

| 规则 | 条件 | 动作 |
| --- | --- | --- |
| R0 空步 | 索引空 | 全量 L2（同 memory_off 文件集） |
| R1 编辑相关 | 指令命中/依赖闭包非空，或任务为代码编辑默认 | `need=true`，ids=闭包 ∪ 编辑候选 |
| R2 无依赖无变更 | 非编辑且闭包空 | `need=false`（不检索，省成本） |
| R3 可见性否决 | 计划省略的文件 **无可见性证明** | 强制 `EXPAND` |
| R4 失败回退 | 验证失败 | 扩大 ids → 全文件 → 仍不足则 `INSUFFICIENT_CONTEXT` 标记 |

EMC **不** 生成自然语言“记忆故事”；只产出结构化计划与日志。

### 3.2 可见性追踪（修复主因）

```python
class VisibilityTracker:
    """仅当文件完整源码出现在当前 messages 可见文本中，才允许省略。"""
    def mark_sent(self, relpath: str, content: str) -> None: ...
    def has_visible(self, relpath: str, content_hash: str) -> bool: ...
    def proof(self, relpath: str) -> dict: ...
```

- 哈希源：**实际写入 messages 的文本**（context 或 assistant FILE 块），不是“曾经 sync 过”。  
- assistant 响应写入历史后，用 `parse_file_blocks` 重新 `mark_sent`。  
- 省略谓词 O′（相对 V1.0 的 O）：

```text
O′ = hash_match ∧ previously_visible_in_messages ∧ file_not_in_current_ctx
     ∧ validity != tombstoned_unsafe ∧ not_edit_target_candidate
```

任一失败 → **不得省略**，回退 EXPAND。

### 3.3 验证器（安全注入）

对每个拟注入/拟省略的 symbol：

1. **完整性**：`content_hash` vs 当前 workspace 字节。  
2. **版本**：`version` 与 store 一致；stale → 禁止 REUSE，EXPAND。  
3. **依赖**：变更闭包内的 caller/provider 若不可见且任务可能触及 → 强制纳入 L2。  
4. **失败**：`ValidateResult{ok, reason, action}`；禁止伪造记忆内容。

### 3.4 装配器（注入）

- **禁止**在上下文塞入长篇 MODE 协议说明（V1.0 +23 tokens 且可能扰动 1.5B）。  
  改用极短行：`[ctx] files:` 或无 MODE 行（消融项）。  
- 文件块格式与 memory_off **同构**（`--- FILE … ---`），降低分布偏移。  
- L1 目录注入默认关闭；开启时上限 `max_l1_lines`（默认 8 行）。  
- 编辑目标文件：**始终 L2 全源**（本任务集 2 步小仓库，全源成本可接受且必要）。

### 3.5 注入审计（前后）

`logs/injection_audit.jsonl` 每步一条：

```json
{
  "step": "step2",
  "plan": {"need": true, "ids": ["…"], "mode": "expand"},
  "pre":  {"visible_files": ["app.py"], "missing": ["lib.py"]},
  "checks": [{"symbol_id": "…", "hash_ok": true, "action": "EXPAND"}],
  "post": {"injected_files": ["app.py", "lib.py"], "omitted": []},
  "fallback": null,
  "cost_ref": "ledger:…"
}
```

### 3.6 成本账本 CostLedger

每步累计（写入 result + 汇总 JSON）：

| 字段 | 含义 |
| --- | --- |
| `tokens_prompt/completion/total` | API 真实计数 |
| `cost_index_ms` | sync/索引 |
| `cost_route_ms` / `cost_route_tokens_est` | EMC |
| `cost_assemble_ms` / `injected_chars` / `omitted_chars_est` | 注入 |
| `cost_fallback_events` | 回退次数 |
| `verified_safe_omission` | O′ 成立的文件数 |
| `latency_model_ms` | 模型墙钟 |

**Verified Safe Omission** 仅统计 O′ 通过的省略；失败步成本 **必须** 计入 episode 总账。

## 4. 调用流程（vam_coder_v1.1）

```text
open_memory → initial_sync → MutationLog.append(INIT)
for step in episode:
    sync()                    # 动态记忆更新；L0 重算闭包
    plan = EMC.decide(task, index, visibility, budget)
    plan = Validator.enforce(plan)          # R3/R4
    ctx   = Assembler.build(plan, visibility)
    audit = InjectionAudit.record(pre, checks, post)
    messages = [system] + visible_history + [user(task, ctx)]
    resp = model(messages)
    visibility.mark_from_assistant(resp)
    apply_edits → store.update_entries(version++)
    CostLedger.add(...)
```

与 V1.0 差异（行为开关 `architecture_version`）：

| 行为 | v1.0 | v1.1 |
| --- | --- | --- |
| 省略条件 | history_sent 哈希 | O′ 可见性证明 |
| tombstone 文件 | 整文件 DROP | 符号 DROP；文件若仍是编辑/依赖目标则保留 L2 |
| MODE 长说明 | 有 | 默认无（可开） |
| EMC | 无（逐符号 P0 路由） | 有计划层 |
| 审计/账本 | 部分 | 强制 |

P0 `RuleRouter` **保留只读**；V1.1 控制器可调用其 validity 门控作为底层，但省略裁决权在 EMC+Visibility。

## 6. 数学定义（评价用）

Episode 集 \(\mathcal{E}=\{(task,rep)\}\)，步 \(\{1,2\}\)。

- Episode 成功率  
  \(\mathrm{ESR}=\frac{1}{|\mathcal{E}|}\sum_e \mathbf{1}[s_1=1 \land s_2=1]\)

- 检索成功率（EMC need=true 时，计划所需文件在注入后均可见或已证明可见）  
  \(\mathrm{RSR}=\frac{\#\{need\land all\_planned\_visible\}}{\#\{need\}}\)

- 无效/过期检索率  
  \(\mathrm{ISR}=\frac{\#\{injected\land (stale\lor hash\_mismatch)\}}{\#\{injected\}}\)（V1.1 目标 0）

- 每成功 episode 总 token  
  \(\mathrm{TPSE}=\frac{\sum_e \sum_{t\in e} (P_t+C_t)}{\sum_e \mathbf{1}[e\ success]}\)

- 净省略（Verified Safe Omission）  
  \(\mathrm{VSO}=\sum_{t} \mathrm{files}(O′_t)\)

效率收益：\(\mathrm{TPSE}_{v1.1} \le (1-\delta)\,\mathrm{TPSE}_{memory\_off}\) 且 \(\mathrm{ESR}\) 非劣（见实验协议，**预注册**）。

## 7. 预期收益（假设，非结论）

1. **准确率**：消除“盲区省略”后，RUR02/RUR03/DEL01 等空上下文失败应显著减少；ESR 应接近 symbol_full_read（同源码注入）而非 memory_off 以下。  
2. **效率**：仅在 O′ 成立时省略；2 步短 episode 上净省略可能仍小——这是真实结果，不靠虚增 omitted。长期多步场景收益随可见 assistant 内容增长。  
3. **安全**：ISR→0；无法确认时显式 `INSUFFICIENT_CONTEXT`，不伪造。  
4. **成本可见**：回退与审计不再被 omitted_est 掩盖。
