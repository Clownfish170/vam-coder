**不依赖启动命令退出码**：以 `/v1/models` + `netstat` + 进程表为准。

### B.2 `ChildProcess.kill` 根因（事实）

该错误出现在 **Bash 工具包装层** 对子进程的清理，对应一次失败的后台启动尝试：

```text
cmd //c start /b llama-server.exe ...   →  ChildProcess.kill / Unknown
```

原因：`start /b` 与工具会话的 job/子进程生命周期不兼容，工具在超时/清理时杀掉管道，表现为 `ChildProcess.kill`。  
**不是** llama-server 自身崩溃，也 **不是** 模型加载失败。

### B.3 可靠启动路径（已验证）

后续成功路径为 Python `subprocess.Popen(..., creationflags=CREATE_NO_WINDOW)` + 轮询 `/v1/models`：

1. 写日志到 `p1/results/llama_server_v11.log`  
2. 轮询最多 ~40s  
3. 收到 `{"models":[...]}` 才判定 ready  

### B.4 残留风险

## E. V1.1 机制代码审查（只读）

审查文件：`p1/scripts/v11/{visibility,controller,assemble,audit}.py`、`run_p1_v11.py`。  
**本阶段未修改上述文件。**

### E.1 对照表

| 审查项 | 结论 | 位置 / 证据 |
| --- | --- | --- |
| 目标文件强制 EXPAND | **是** | controller：`must_expand = touched ∪ force_visible`；stale/unverified 全文件 EXPAND（`R4_nonvalid_forces_expand`） |
| 非目标可靠可见性证明 | **是** | 仅 `REUSE_KV` 候选走 O′；`tracker.has_visible(rel, sha)` 要求 messages 内哈希一致 |
| 哈希不匹配回退 | **是** | `apply_visibility_veto` + `safe_omission` → assemble 升 EXPAND，`fallback_events++` |
| 版本变化回退 | **间接是** | 依赖 store validity：stale/unverified → EXPAND；**未**在 O′ 内直接比较 `version` 字段（见 E.2 缺口） |
| 依赖变化回退 | **部分是** | 失效符号的文件与调用方进 `must_expand`；**不是**全量传递闭包重算（见 E.2） |
| 回退真正注入完整源码 | **是** | `assemble` EXPAND 路径 `_file_block` 读 workspace 当前文件 |
| 缺失文件正确报告 | **是** | `content is None` → `INSUFFICIENT`，不伪造，`insufficient=True` |
| 审计 vs messages 一致 | **验证 run 16/16 一致** | §B/验证：`injected_files` ≡ context FILE 集；omitted ∩ context = ∅ |
| `metadata.verify_symbol_injection` | **未接入主路径** | 模块存在但 `run_p1_v11`/`assemble` 未调用 |

### E.2 已知缺口（记录，本阶段不修）

1. **version 显式比较**：O′ 依赖 validity 传播，而非 `entry.version` 单调性；validity 漏标时可能漏回退（H，低概率）。  
2. **依赖闭包偏窄**：`dependency_closure_files` 只收集 stale/unverified 相关及依赖它们的调用方；合法 valid 依赖链变更未全量展开（对 2 步任务影响有限）。  
3. **文件名子串匹配**：`base in instruction` 可能误命中（如 `a.py` ⊂ `active`）；验证子集未观察到有害后果。  
4. **DROP 死路径**：assemble 支持 tombstoned DROP，EMC 当前不产 DROP；tombstone 仍以整文件 EXPAND 为主（偏安全）。  
5. **run_p1_v11 不支持 v1.0 基线**：B 组必须走 `run_p1.py`（消融协议已写明）。

### E.3 主路径数据流（审查用）

```text
sync(store) → entries_by_file + workspace_sha
→ MemoryController.decide (R0–R4)
→ apply_visibility_veto
→ assemble_vam_v11 (O′ / fallback EXPAND / INSUFFICIENT)
→ InjectionAudit.record
→ build_messages(ctx)
→ model → mark_from_assistant
```
