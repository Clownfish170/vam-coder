# P1-v0.2 实验协议

适用范围：`p1/` 脚手架 v0.2（任务集 `p1-v0.2.0`）。冻结 P0 = `a31a0c1`（不修改）。
本协议在正式 20–30 episode 实验前生效；所有历史 v0.1 运行记录保留，判据以各自
`run_meta.tasks_sha256` / eval 哈希为准。

## 1. 能力边界（不可违反的表述）

- `REUSE_KV` 是**文本上下文省略代理**：仅当符号当前内容哈希与对话中已发送
  内容一致时，才从提示词中省略该内容。**不是**真实 KV 张量复用，不主张任何
  KV 加速或显存收益。
- 服务端若返回 `cached_tokens` / `prompt_tokens_details` 等字段，原样保存在
  `request.json.usage_raw` 与 `result.json.raw_usage`，单独解释；服务端不提供
  的字段保持缺失，禁止估算伪造。
- token 三分：`prompt_tokens`（API 真实计数）/ `router_est_tokens`（P0 chars/4
  估算，仅覆盖记忆块）/ `context_tokens_est`、`history_tokens_est`（装配与历史
  的 chars/4 估算）。三者不可混用。

## 2. 基线定义

| 基线 | 类型 | 每步上下文 | 记忆行为 |
| --- | --- | --- | --- |
| `memory_off` | 主基线 | 工作区全部当前 `.py` 源码 | 无 store |
| `symbol_full_read` | 主基线 | 索引内全部存活符号所在文件全文 | 每步 sync，无路由 |
| `fixed_summary` | 主基线 | 仅 episode 开始冻结的摘要 | 一次初始 sync，此后冻结 |
| `vam_coder` | 主基线 | 按 P0 路由决策装配 | 每步 sync+route；EXPAND=全文件、COMPRESS=摘要、REUSE_KV=哈希命中才省略、DROP=丢弃 |
| `refreshed_summary` | 对照（任务 6-B） | 每步刷新的摘要（无源码） | 每步 sync 更新摘要，**不**做版本失效门控（tombstone 除外） |

对照设计：`fixed_summary`（冻结摘要）vs `refreshed_summary`（新鲜摘要）隔离
“摘要过期”因子；二者均无源码，与“有源码”基线对比隔离“无源码”因子。
不看结果调整任何判据。

## 3. 计时口径（单调时钟 `perf_counter`，毫秒）

| 字段 | 定义 |
| --- | --- |
| `t_initial_sync_ms` | episode 级初始 sync（建索引/冻结记忆）。每 episode×基线**只计一次**，仅出现在 step1 行；**不计入**任何 `t_step_ms` |
| `t_sync_ms` | 步内增量 sync（fixed_summary 步内恒 0） |
| `t_route_ms` | `route_repo()` 调用（仅 vam_coder） |
| `t_assemble_ms` | 上下文装配函数（不含写盘） |
| `t_model_ms` | HTTP 请求墙钟（网络+排队+prefill+generation，不可拆分） |
| `t_eval_ms` | 隔离 pytest 子进程 |
| `t_step_ms` | 步内合计：步内 sync→eval + 产物写盘（context/messages/request 等） |
| `t_episode_ms` | `t_initial_sync_ms + Σ t_step_ms`（写于 episode_summary） |

一致性约束（`check_run_integrity.py` 强制）：
每行 `t_step_ms ≥ t_sync+t_route+t_assemble+t_model+t_eval − 5ms`（写盘余量）；
`t_initial_sync_ms` 非零仅允许 step1 且基线 ∈ 记忆类；memory_off 恒为 0。
系统开销与模型请求耗时**永不合并**为单一字段。

## 4. History policy（四基线统一）

- 消息保留：system + episode 内全部 user/assistant 轮；
- 预算：`--max-history-chars`（默认 24000 字符 ≈ 6000 估算 token）；
- 截断：从最旧的 user+assistant **对**开始丢弃，直到 ≤ 预算；system 与当前
  轮永不截断；`history_pairs_dropped` 逐行记录；
- 四基线调用同一 `trim_history()`，同一预算，同一规则。

**已知影响（必须随结果报告）**：保留 assistant 历史意味着所有方法都能从
模型先前写过的文件中看到源码；这对手一致，但会稀释“无源码”基线的饥饿程度。
统一历史 ≠ 各方法输入相同：方法装配的 CONTEXT 段仍由各自规则决定。

每次请求记录：`n_messages`、`history_tokens_est`、`context_tokens_est`、
API `prompt_tokens`。

## 5. 基线执行顺序

`offset = (episode_index + rep) % N`，顺序 = baselines 右旋 offset；
`rep` 由 `--rep` 指定（默认 1）。实际顺序写入 `baseline_orders.json` 与每行
`baseline_order_index` / `rep`。正式实验每个 (episode, rep) 一条独立 run 目录。

## 6. 版本冻结与清单

- `python p1/scripts/make_manifest.py --name <immutable_name>` 生成
  `p1/manifests/<name>.json`（脚本/测试/tasks/各 project/各 eval 的 SHA-256，
  含逐文件清单）；**拒绝覆盖**已有清单。
- `run_p1.py` 启动时重算并与最新（或 `--manifest` 指定）清单比对；不一致 →
  退出码 3，禁止运行（`--allow-manifest-mismatch` 仅限开发）。
- 判据/脚本变更流程：升 `task_set_version` → 改文件 → 新清单名 → 提交。
  历史 run 的哈希永远指向旧版，不被替换。

## 7. 运行与产物

- 输出目录 `p1/results/runs/<run_id>/`；`run_id` 已存在且非空 → 拒绝（退出 2）。
- 每步：`context.txt`、`prompt.txt`、`messages.json`、`request.json`、
  `response.txt`（真实运行）、`apply.json`、`eval_output.txt`、`result.json`。
- 脱敏：不记录任何请求头/Authorization；本客户端不发送密钥。
- 失败分类建议（分析阶段）：`MODEL_NO_EDIT / MODEL_BAD_FORMAT /
  MODEL_WRONG_SEMANTICS / APPLY_REJECTED / EVAL_FAIL / MODEL_HTTP_ERROR /
  HARNESS_ERROR`；原始记录不改。

## 8. 复用量三口径（vam_coder）

| 字段 | 含义 |
| --- | --- |
| `reuse_decisions` | REUSE_KV 决策次数（含同文件被 EXPAND 带回的情况） |
| `reuse_omitted` / `reuse_omitted_files` / `reuse_omitted_bytes` | 文件级实际省略：整文件因哈希命中未展开时的符号数/文件数/字节数 |
| `reuse_without_omission` | REUSE_KV 决策发生但同文件因 EXPAND 仍被展开 → 无省略 |
| `expand_included_bytes` | 因 EXPAND/回退读取纳入的源码字节数 |

**决策次数不等于 token 节省**；实际收益以最终请求的 API token 及
`request.json` 为准。

## 9. 正式实验运行命令（示例；本轮不启动全量）

```bash
python p1/scripts/make_manifest.py --name p1_v0.2_manifest   # 已存在则勿重复
python p1/scripts/run_p1.py --episode all --baselines all --rep 1 \
  --endpoint http://127.0.0.1:8080/v1 --model qwen2.5-coder-1.5b
python p1/scripts/check_run_integrity.py p1/results/runs/<run_id>
```
