## 0. 审查结论先行（对候选四层）

| 候选层 | 提案含义 | 审查结论 |
| --- | --- | --- |
| L0 稳定规则/项目约定/通用知识 | 可注入的“内部静态表示” | **删除独立层**。2 步 Python 编辑任务的约定极稳定，应固化在 system prompt / 任务集，**不得**每步注入长文。重复注入只会重蹈 V1.0 MODE 话术开销。 |
| L1 符号索引（ID/类型/摘要/版本/依赖） | 外部寻址 | **保留为内部索引**（P0 store 扩展），默认 **不整表注入**。可选“目录行”注入。 |
| L2 结构化记忆（签名/局部代码/调用关系） | 中间层 | **条件保留**：仅用于 **非编辑目标** 的相关文件摘要；**编辑目标禁止停在 L2**（见 §2.2）。 |
| L3 原始全源 | 完整源码 | **保留**，编辑/失效/依赖闭包的必需层。 |

**V1.2 最终可注入层级 = 三级，不是四级：**

```text
[内部] Index   ≈ 原 L0+L1 合并：符号表、哈希、依赖、validity、任务相关性（不进 prompt）
[可选] Digest  ≈ 原 L2 的子集：非目标文件的一行摘要/签名（进 prompt，便宜）
[必需] Full    ≈ 原 L3：当前 workspace 全文件（编辑目标与风险文件）
```

原则：**少一层比多一层好**；每层必须有可观测的 TPSE 收益或 ESR 非劣证据，否则合并。

## 1. V1.1 数据流（实际代码路径）

```text
tasks_v1.0.json.episodes[id]
  → copy project → workspace
  → open_memory + manager.sync          # 动态记忆 / validity
  → build_v11_plan:
        entries_by_file + dependency_closure_files
        MemoryController.decide (R0–R4)
        apply_visibility_veto (O′ 预检)
  → assemble_vam_v11:
        REUSE_KV 仅当 safe_omission O′ 通过
        否则 fallback → EXPAND 全源
        缺失文件 → INSUFFICIENT（不伪造）
  → InjectionAudit.record
  → build_messages(system + assistant_history + user(task, ctx))
  → chat_completion
  → mark_from_assistant / apply_blocks / eval
  → CostLedger
```

关键不变量（V1.1 已建立，V1.2 必须保持）：

1. 省略仅当 **messages 可见哈希证明**（O′），不是 `history_sent`。  
2. 回退必须把 **当前磁盘全源** 放进 context。  
3. 审计 `injected_files` ≡ context FILE 块（验证 run 16/16）。  
4. V1.0 / V1.1 基线可复现；新架构独立 baseline 名。

## 3. V1.2 目标架构

### 3.1 设计不变式

1. 保留双层 Token 研究方向：**内部可复用表示** + **符号 ID 寻址**。  
2. O′ 可见性安全省略继续有效（Full 层）。  
3. 不依赖大模型工具调用；1.5B 可运行。  
4. 单步内渐进展开默认 **无额外模型调用**（确定性充分性检查）。  
5. V1.1 作为可切换基线完整保留。

### 3.2 模块图

```text
                    Task instruction
                           │
              ┌────────────▼────────────┐
              │ TaskAwareController     │  ← V1.2 新增/升级 EMC
              │  r(f|t) 相关性           │
              │  LevelPolicy π(L|f,t)   │
              │  SufficiencyCheck       │
              └────────────┬────────────┘
                           │ ExpandPlan
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
   Index (internal)   Digest inject    Full inject
   (P0 store)         (optional)       (O′ / must)
         │                 │                 │
         └─────────────────┴─────────────────┘
                           │
                    Assembler + Audit
                           │
                    VisibilityTracker O′
                           │
                    Model (FILE protocol)
```

### 3.3 三级记忆规格

#### A. Index（内部；不默认进 prompt）

| 字段 | 来源 | 生命周期 |
| --- | --- | --- |
| symbol_id, file_path, kind | P0 parse/sync | sync 重建 |
| content_hash, source_hash, version | store | 编辑后 +1 |
| deps / validity | invalidation | sync 迁移 |
| file_sha256 | workspace | 每步 |
| r(f\|t) | 控制器 | 每步 |
| level_target | LevelPolicy | 每步 |

**失效条件**：hash 变化 → stale；依赖变 → unverified；删除/改名 → tombstoned。  
**读写**：仅 harness 读写；模型不可直接写 Index。

#### B. Digest（可选注入）

格式（每文件一行，目标 **≤12 tokens** 量级）：

```text
--- INDEX file.py [fn=hot,fa] v3 ok ---
```

或极短签名行（仅当 level_target=SIG）：

```text
--- SIG file.py ---
def hot() -> int
```

规则：

- **编辑目标、stale、unverified、依赖闭包内文件 → 禁止仅 Digest**。  
- Digest 只用于：说明“存在但本步不要求全源”的文件，避免模型完全无知。  
- 无独立生成模型；签名来自 AST/正则解析（可解释、可测）。

#### C. Full（必需层）

与 V1.1 相同：`--- FILE f.py (full current source) ---` + 当前磁盘内容。  
仍走 O′：若 Full 可被安全省略则省略（跨步 assistant 可见哈希命中）。

### 3.4 任务感知控制器（TaskAwareController）

在 V1.1 MemoryController 上扩展，规则仍为 **确定性、可单测**。

#### 3.4.1 编辑目标识别（独立于相关性评分；r2.2 强化）

`edit_targets(τ)` **不** 使用 \(r(f\mid τ)\)，而用 **正向编辑意图 + 否定作用域** 的解析器（**r2.2 新增，非 r2.1 原有**）：

| 优先级 | 规则 | 示例 |
| --- | --- | --- |
| P1 | **仅在正向编辑子句**上做路径/符号 **token 级精确匹配**（词边界） | 「修改 hot.py」→ hot.py |
| P2 | **否定编辑子句**（不要修改/保持不变/禁止改动 等）管辖的路径 → **`Excluded`**，**不进** edit_targets | 「不要修改 beta.py」→ beta ∉ E |
| P3 | 符号精确名且唯一文件 | `hot()` → hot.py |
| P4 | 歧义多文件 → 全部入 E（保守） | `norm` DUP01 |
| P5 | 模糊子串仅审计 | `fuzzy_hits` |
| P6 | 解析不清且非全库膨胀 | 相关候选 → **`CandidateFull`**（**≠** E）+ `target_resolution_reason` |
| P7 | 同文件正向+否定冲突 | 保守入 E + reason=conflict |

`EditTargets` **必须** \(E_t\subseteq M_t\)（must_full），与 \(r\) 无关。

**集合关系（r2.2 定稿）**：

\[
E_t\cap C_t=\varnothing,\quad
E_t\cup C_t\subseteq F_t,\quad
E_t\subseteq M_t
\]

- \(C_t\)：CandidateFull，**不必** 属于 \(M_t\)；但必须 \(C_t\subseteq F_t\)。  
- \(M_t\) 可含非编辑目标（依赖/risk）。

#### 3.4.2 编辑目标与 Candidate 的注入义务（r2.2）

| 集合 | 本轮 FULL | O′ | \(K_{\max}\) | 发送前验证 |
| --- | --- | --- | --- | --- |
| \(E_t\) EditTargets | **必须** \(E_t\subseteq F_t\) | **禁止** | **豁免** | `edit_target_full_verified` |
| \(C_t\) CandidateFull | **必须** \(C_t\subseteq F_t\) | **默认禁止** | **豁免** | `candidate_full_verified` |
| \(M_t\setminus(E\cup C)\) | 依赖/risk | 允许 O′ | 豁免 | O′ 发送前校验 |
| 可选 Full | 按策略 | 允许 | **受约束** | 普通 O′ |

**CurrentContext 验证对象**：最终实际发送给模型的 **messages**（阶段 B 之后），**不是** assemble 内部集合，**不是** 仅历史 assistant。  
历史 assistant 中 FILE **即使 hash 一致也不得** 代替 \(E/C\) 的本轮 FULL。  
任一 \(E\) 或 \(C\) 验证失败 → **`INSUFFICIENT`**，禁止请求模型。

**硬约束（写入运行时）**：

\[
\forall f\in E_t\cup C_t:\quad
FullFile(m,f)\ \land\ Hash(m,f)=Hash(Disk_t,f)
\]

#### 3.4.3 must_full 与预算

**must_full \(M_t\) 定义（不可静默缩减）**：

1. \(E_t\)（**必须**包含，\(E_t\subseteq M_t\)）  
2. `validity ≠ valid` 的文件  
3. **依赖闭包** \(\mathrm{dep}_{\leq d}^{+}\cup\mathrm{callers}_{\leq d}\)（d=2 已冻结）  
4. **不包含**仅为否定而排除的 \(Excluded\) 文件（除非落入 2/3）

**\(K_{\max}\)**：仅约束可选 Full；\(E_t\cup C_t\cup M_t\) **豁免**。

若 \(\mathrm{est}(system+history+must+digest)>W\)：INSUFFICIENT / REQUIRED_CONTEXT_EXCEEDS_LIMIT（不变）。

#### 3.4.4 规则表（r2.2）  
- 设置 `over_kmax=true`；  
- **禁止** 为凑 \(K_{\max}\) 静默丢弃 must_full。

若 \(\mathrm{est}(must_{\mathrm{full}}) + \mathrm{est}(digest) > B\)（预算 B）：

- **仍完整注入 must_full**；  
- 丢弃 **全部** 可选 DIGEST（可再丢可选 FULL 升级）；  
- `over_budget=true`，`insufficient=false` 仅当 must_full 仍满足且未超模型上下文窗；  
- 若磁盘缺失导致 must_full 无法满足 → `INSUFFICIENT`，`reason=MISSING_REQUIRED_FILE`；  
- 若 \(\mathrm{est}(\mathrm{system}+\mathrm{history}+\mathrm{must}+\mathrm{digest}) > W\)（服务端上下文窗）→ **仍不得截断 must/降 Digest/静默丢历史**；`INSUFFICIENT`，`reason=REQUIRED_CONTEXT_EXCEEDS_LIMIT`；记录 `required_context_tokens_est`、`available_context_tokens`（计 INSR）。

#### 3.4.4 规则表（r2.2）

| 规则 | 条件 | level |
| --- | --- | --- |
| T0 空索引 | index 空 | 全部 FULL |
| T1 编辑目标 | \(f\in E_t\) | **FULL**，禁 O′ |
| T1c 候选 | \(f\in C_t\) | **FULL**，默认禁 O′ |
| T2 风险文件 | validity ≠ valid | **FULL** |
| T3 依赖闭包 | \(f\in \mathrm{dep}_{\leq d}^{+}(E_t)\cup\mathrm{callers}_{\leq d}(E_t)\) | **FULL** |
| T4 相关非目标 | \(r\ge τ_D\) 且非 must | **DIGEST** |
| T5 无关 | \(r < τ_D\) | **NONE** |
| T6 预算 | 累计 est > B | **仅**降可选；**永不**降 E/C/M |
| T7 可见性 | Full 且 O′ 可省且 \(f\notin E_t\cup C_t\) | 可 omit |
| T8 上下文窗安全 | est > W | INSUFFICIENT（不变） |

#### 3.4.5 审计字段（含 r2.2）

```json
{
  "must_full_count": 3,
  "k_max": 8,
  "over_kmax": false,
  "edit_targets": ["alpha.py"],
  "candidate_full": [],
  "excluded": ["beta.py"],
  "edit_target_full_verified": true,
  "candidate_full_verified": true,
  "insufficient": false,
  "insufficient_reasons": [],
  "target_resolution_reason": {"alpha.py": "positive_edit_clause"}
}
```

`edit_target_full_verified` 与 `candidate_full_verified` **分列**，禁止合并为单一 `full_verified`。

#### 3.4.6 装配顺序（r2.2）

```text
Pass 1  解析 E/C/Excluded（正向/否定）→ M = E ∪ risk ∪ dep_closure（E⊆M）
Pass 2  非 must：DIGEST/NONE/可选 FULL（受 K_max/B）
Pass 3  强制 E∪C FULL（禁 O′）；M\E 可 O′ 候选
Pass 4  build_messages → 对 E、C 分列验证 → 失败 INSUFFICIENT → 否则发送
```

### 3.5 渐进式展开（上下文粒度自适应）— 单步确定性

**命名澄清（审查）**：本机制是 **task-aware adaptive context assembly**（单步内按充分性选择粒度），**不是** 多轮 agent 式 progressive disclosure。实验臂 F 称 **context-granularity ablation**，不称 “关掉 PE”。

**不做**默认多轮模型问答。单步内装配顺序以 **§3.4.6**（E/C 强制 FULL + 发送前分列验证）为准。

停止条件：

| 条件 | 含义 |
| --- | --- |
| S1 | \(E_t\cup C_t\subseteq F_t\)（发送前 verified）；其余 must 为 injected ∪ O′ |
| S2 | 无更多可选升级（或已触 B / \(K_{\max}\) 对可选项） |
| S3 | \(K_{\max}\) **仅**停止可选 FULL；不阻止 E/C/M |
| S4 | `max_model_feedback_rounds=0` |

**禁止**：

- 同 step 内 F→D 降级循环；  
- 静默丢 must_full；  
- 把 \(K_{\max}\) 写成“超过 8 个必须文件就丢弃”；  
- 用历史 assistant 省略代替 E/C 本轮 FULL。

## 4. 1.5B 适配约束

| 约束 | 设计响应 |
| --- | --- |
| 需完整 FILE 块协议 | 编辑目标必须 Full |
| 不可靠“缺什么”元对话 | 默认 0 轮模型反馈 |
| 对长说明敏感 | Digest 行极短；无长 MODE |
| 算术/改错仍会失败 | 不把 STM02 类失败算作架构 KPI 主因 |

**结论**：V1.2 必须是 **harness 侧渐进**，不是 agent 工具循环渐进，才能在 Q6_K 1.5B 上可运行、可归因。

## 5. 预期收益（假设，非结论）

1. **TPSE**：相关非目标从 Full 降为 Digest → 短 episode 上有机会逼近或低于 memory_off（H1）。  
2. **ESR**：编辑目标仍 Full，风险文件仍 Full → 应接近 V1.1，且优于危险省略。  
3. **安全**：O′ 保留；危险省略次数保持 0（相对关回退消融）。  
4. **复杂度**：相对候选四层，减少一个不可验证的“可注入 L0”，降低实现与审稿成本。
