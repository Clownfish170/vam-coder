## 1. 符号与可观测量

### 1.1 集合

| 符号 | 含义 | 观测 |
| --- | --- | --- |
| \(e \in \mathcal{E}\) | episode = (task, rep) | run 目录 |
| \(s \in S_e=\{1,2\}\) | 步 | per_step |
| \(f \in \mathcal{F}_e\) | workspace 源文件 | 磁盘枚举 |
| \(\tau_s\) | 任务指令文本 | tasks_v1.0.json steps |
| \(L \in \{N, D, F\}\) | NONE / DIGEST / FULL | ExpandPlan / audit |
| \(E_s\) | EditTargets（正向编辑意图） | targets 解析 |
| \(C_s\) | CandidateFull（保守候选） | targets 解析 |
| \(M_s\) | must_full | plan |
| \(F_s\) | FullInjected（最终 messages 完整 FILE） | 阶段 B 验证 |

**r2.2 集合约束（硬）**：

\[
E_s\cap C_s=\varnothing,\qquad
E_s\cup C_s\subseteq F_s,\qquad
E_s\subseteq M_s
\]

### 1.2 准确率（保留）

**Episode Success Rate（主）**

\[
\mathrm{ESR}=\frac{1}{|\mathcal{E}|}\sum_{e}\mathbf{1}\big[\forall s\in S_e,\ \mathrm{eval}_s=1\big]
\]

| 项 | 定义 |
| --- | --- |
| 分子 | 两步均 eval_success=1 的 episode 数 |
| 分母 | 臂内全部 episode-runs（error 记 fail） |
| 范围 | 单臂 × 单任务集 × 同 R |

**Step Pass Rate（辅）**

\[
\mathrm{SPR}=\frac{\sum_{e,s}\mathrm{eval}_s}{\sum_e |S_e|}
\]

分子：pass 步；分母：总步；error 步计 0。

### 1.3 Token 成本指标（审查新增/澄清）

\[
T(e)=\sum_{s\in S_e}(P_s+C_s),\qquad \mathrm{succ}(e)=\mathbf{1}[e\ \mathrm{success}]
\]

| 指标 | 公式 | 分子 | 分母 | 范围 |
| --- | --- | --- | --- | --- |
| **TPAE** Tokens per Attempted Episode | \(\sum_e T(e)/|\mathcal{E}|\) | 臂内全部 episode token | 尝试次数 | 全臂，**含失败** |
| **TPSE** Tokens per Successful Episode | \(\sum_e T(e)/\sum_e\mathrm{succ}(e)\) | 同上 | 成功数 | **主效率** |
| **FETC\_total** Failed Episode Token Cost（合计） | \(\mathrm{FETC}_{total}=\sum_{e:\neg succ}T(e)\) | 失败 episode token 合计 | — | 仅失败 |
| **FETC\_mean** | \(\mathrm{FETC}_{mean}=\mathrm{FETC}_{total}/N_{fail}\)；\(N_{fail}=0\) 时 **NA** | 同上 | \(N_{fail}\) | 仅失败 |

\(T(e)\) 含该 episode **全部实际请求**（含 HTTP 错误重试一次后仍发出的 token）。

**防“早失败刷低 TPSE”**：

1. 主表固定四列：**ESR, TPAE, TPSE, FETC**。  
2. 效率优势须同时：ESR 非劣 **且** \(\mathrm{TPAE}_X\le 1.05\cdot\mathrm{TPAE}_{ref}\)。  
3. 若 \(\mathrm{TPSE}_X<\mathrm{TPSE}_Y\) 但 \(\mathrm{ESR}_X<\mathrm{ESR}_Y-0.05\)，**禁止**单独用 TPSE 宣称 X 更高效。

**每步分量（不变）**：\(P_s,C_s,T_s\) API；\(I^{idx/route/asm}\) harness ms；\(L^{model}\)；\(N^F,N^D\)；\(V_s,B_s\)。

**Prefill**：\(P_s\) 主；\(\mathrm{cache}_s\) 仅服务端前缀缓存，**禁止**当 VAM KV 显存收益；真实 KV **not measured**。

### 1.4 检索、安全、超预算

| 指标 | 定义要点 |
| --- | --- |
| RSR | must_full 步：must ⊆ injected ∪ O′_proved |
| ISR | trusted Full 且 hash≠ws（目标 0） |
| FBR | fallback / 有升级机会步 |
| DHO | 危险省略（目标 0） |
| **OBR** | \(\#\{over\_budget \lor over\_kmax\}/\#steps\) |
| **INSR** | \(\#\{insufficient\}/\#steps\) |

审计 JSON 见 `v1.2_architecture_design.md` §3.4.4。

## 2. 相关性 \(r\) 与编辑目标解耦

**edit_targets(τ)**：仅由架构 §3.4.1 **精确解析**（路径 token / 符号精确名），**不得**调用 \(r\)。

\[
r(f\mid\tau_s)=
w_1\mathbb{1}[\mathrm{basename\_token}]
+w_2\mathbb{1}[f\in\mathrm{dep}^+(\mathrm{targets})]
+w_3\mathbb{1}[\mathrm{nonvalid\ in}\ f]
+w_4\mathrm{lex}
\]

- \(r\) 只用于 **非 must** 的 DIGEST/NONE 与可选 FULL 升级排序。  
- 模糊子串仅进 `fuzzy_only_hits`，**不进** must_full。  
- 默认 \(w=(1,1,1,0)\)，\(r\in\{0,1,2,3\}\)。

验证：must_full 漏检编辑目标=0；fuzzy_only ∩ must = ∅。

## 3. 层级策略与 must_full

\[
\pi(L\mid f)=
\begin{cases}
F & f\in E_s\cup C_s\cup\mathrm{must\_full}\\
D & r\ge\tau_D\land\mathrm{budget\_allows}\land f\notin E\cup C\\
N & \text{otherwise}
\end{cases}
\]

\[
M_s=E_s\cup\{f:v_f\neq valid\}\cup\mathrm{dep}_{\leq d}^{+}(E_s)\cup\mathrm{callers}_{\leq d}(E_s)
\]

\[
E_s\subseteq M_s,\qquad
E_s\cup C_s\subseteq F_s,\qquad
E_s\cap C_s=\varnothing
\]

\(C_s\)（CandidateFull）**不必** \(\subseteq M_s\)，但 **必须** \(\subseteq F_s\)。

其中 \(d=\) **closure_depth = 2**（已冻结，见 prereg §8.1）。

**O′ 允许集（r2.2）**：

\[
O'_s\ \mathrm{允许} \iff f\notin E_s\cup C_s
\]

\(E_s\cup C_s\) **默认禁止 O′**；历史 assistant 全文 **不得** 代替本轮 FULL。

**发送前验证（CurrentContext = 最终 messages）**：

- `edit_target_full_verified`：\(\forall f\in E_s\)，最终 messages 含完整 FILE 且 hash=disk。  
- `candidate_full_verified`：对 \(C_s\) 同理。  
- **分列**，禁止合并为单一 `full_verified`。  
- 任一失败 → `INSUFFICIENT`，**禁止**模型请求。

**硬约束**：

1. \(E_s,C_s\) 不得被 \(\pi\) 降为 D/N。  
2. \(E_s,C_s,M_s\) **不受** \(K_{\max}\) 截断。  
3. \(K_{\max}\)（默认 8）只约束 **可选** FULL。  
4. est>B → 丢可选，**必注 E∪C∪M**；记 `over_budget`。  
5. est(system+history+must+digest)>W → INSUFFICIENT / REQUIRED_CONTEXT_EXCEEDS_LIMIT（不变）。  
6. 文件缺失 → INSUFFICIENT / MISSING_REQUIRED_FILE（不变）。

## 4. 充分性与停止

\[
\mathrm{ok}(s)=
\mathbb{1}\big[
E_s\cup C_s\subseteq F_s
\land
(M_s\setminus(E_s\cup C_s))\subseteq \mathrm{inj}_s\cup\mathrm{omit}^{O'}_s
\big]
\]

且 O′ 仅对 \(f\notin E_s\cup C_s\) 生效。

```text
must = targets ∪ risk ∪ dep_{≤d} ∪ callers_{≤d}   # 不经 r
if over_budget or over_kmax:
    audit.over_* = true
    inject ALL must; drop optional
if missing must on disk:
    insufficient=true; reason=MISSING_REQUIRED_FILE
elif est(system+history+must+digest) > W:
    insufficient=true; reason=REQUIRED_CONTEXT_EXCEEDS_LIMIT
    # 不截断 must、不降 Digest、不静默丢历史
    record required_context_tokens_est, available_context_tokens
stop: ok | no optional upgrades | max_model_feedback_rounds=0
```

禁止 F↔D 循环；禁止静默丢 must_full；禁止用丢历史掩盖超窗。  
INSR 可分列：`INSUFFICIENT_missing` 与 `INSUFFICIENT_exceeds_window`（信息检索失败 ≠ 仅预算紧，但超窗时模型收不到完整 must → **不得**记成功安全装配）。

## 5. 成本函数与优化

\[
C_{total}(e)=\sum_{s}\big(\lambda_P P_s+\lambda_C C_s+\lambda_R I_s/1000+\lambda_L L_s/1000\big)
\]

主目标 TPSE，**附加**约束：

\[
\min_\pi\ \mathbb{E}[\mathrm{TPSE}]
\quad\mathrm{s.t.}\quad
\mathrm{ESR}\ge\mathrm{ESR}_{ref}-\varepsilon
\land \mathrm{DHO}=0
\land \mathrm{TPAE}\le 1.05\cdot\mathrm{TPAE}_{ref}
\]

报告强制附 TPAE、FETC。
