## R1 · 历史策略与研究问题的关系重构

**原（rev2）**：策略 A 推荐为“主分析”；策略 B（脱敏）仅为“预注册敏感性
分析（可选）”；未绑定 RQ；未禁止用条件 A 读 stale-summary 因果。

**问题**：[静态] 条件 A 下 `fixed_summary`/`refreshed_summary` 可从**自己**
的 assistant 历史中获得 step1 写出的完整源码（装配上下文虽只有摘要），
`vam_coder` 的省略收益被历史稀释——此时 STM/RFS 的差异混合了“历史补偿”
与“摘要新鲜度”两个因子，不能解释为干净的机制因果；且 rev2 未说明同一
实验内五组必须同策略。

**改动**：
1. §2 定义两个条件：**条件 A**（保留全部历史）= 全部 24 任务，承载
   **RQ1/RQ3 主分析**；**条件 M**（统一 FILE 块脱敏）= **STM01/STM02/
   RFS01/RFS02** 4 任务，承载 **RQ2 主分析**；STM03 不进 M（探索性）；
2. 明确同一条件内五组历史策略、预算、截断完全一致（同一函数）；
3. 解释纪律 4 条：A 的 STM/RFS 只作描述性；RQ2 主结论只来自 M；跨条件
   不合并、不联合检验；方向冲突必须并列报告；
4. §9 拆为 Block A（360 runs）+ Block M（60 runs），`run_meta.history_policy`
   区分 `keep/redact`；§10 RQ2 主分析改指 Block M；
5. §12 增加验收门槛 7：脱敏未通过单测+dry-run 则 Block M 顺延，禁止用
   条件 A 冒充 RQ2 主分析。

**待验证 [待验证]**：脱敏实现与 4 任务 dry-run；Block M 复用条件 A 资格
标签的可操作性（U6）。

## R2 · 安全省略定义统一

**原（rev2）**：§3A 判定表含 V1–V6（V6=估算规模>0），而
`n_verified_safe_omissions` 注释写“= V1–V5 全真的文件数”——判定与计数
口径不一致；估算字段与判定字段未强制分离。

**问题**：[静态] 同一指标在表、计数、验收三处可能按不同条件统计；
若把 `omitted_tokens_est` 混入判定，会出现“估算>0 即省略”的误读。

**改动**：
1. 唯一谓词 `O(F,t) = V1 ∧ V2 ∧ V3 ∧ V4 ∧ V5`；
2. `omitted_tokens_est` 降为**报告字段**（不参与判定；`O=false` 时必须为 0；
   字段名强制 `_est`）；
3. `n_verified_safe_omissions = Σ 1[O=true]`，与谓词严格一致；
   `reuse_decisions`/`reuse_omitted` 保留为兼容列但**禁止**用于机制判定；
4. 四处统一验收：设计 §3A / schema 增补节 / 完整性检查器计数一致性 /
   资格报告 Q3b 直接读谓词；
5. 单测三样例（全真 / 同文件 EXPAND 致 V4 失败 / 未曾发送致 V3 失败）写入
   §3A 与清单 P0-5；
6. 硬性解释规则重申：估算 ≠ 真实 token 节省，表头禁用 “saved tokens”。

**待验证 [待验证]**：assemble_audit 落盘、单测、检查器计数一致性
（清单 P0-5/P0-10）。

## R3 · 机制触发型资格规则（Q3a/Q3b）

**原（rev2）**：Q3 仅检查“声明的失效事件”；RUR02/IRR01/DEL01 的安全省略
机制无检查路径；Q6 在“全过+省略为 0”时可标 TRIVIAL，可能掩盖省略机制
未触发。

**问题**：[静态] 规则漏洞：任务以省略机制为设计目标但资格测试中谓词从未
为真时，若五组全过，会落入 Q6 而非 REVIEW/EXCLUDE。

**改动**：
1. 规则拆分：**Q3a**（失效类：stale/unverified/tombstone 事件，读
   invalidation JSONL）；**Q3b**（省略类：读 assemble_audit 谓词，
   **仅适用于预声明省略的 RUR02/IRR01/DEL01**，不套用其他任务）；
2. 新增**机制预声明表**：24 任务逐行给出 Q3a 检查事件（含 step 位置）与
   Q3b 期望（3 个省略任务的 step 与期望计数；其余标“无/0”）；
3. Q3b 动作 = REVIEW 三分诊断（模型违例→标注保留 / 实现缺陷→修码重测 /
   规格不可达→EXCLUDE-设计），**任何情形禁止因全过改判 TRIVIAL**；
4. Q6 增加前置：声明省略的任务必须 Q3b 通过才可落 TRIVIAL；
5. 应用顺序固定 Q1→Q2→Q3a→Q3b→Q4→Q5→Q6。

**待验证 [待验证]**：Q3a/Q3b 检查器实现（清单 P0-9）与资格测试实跑。

## R4 · RUR02 可实现性核查

**原（rev2）**：「vam 两步均应对 stable_a/stable_b 产生已验证安全省略」。

**问题与分析**：
1. [已执行-静态核对] 谓词 V3 要求“本步之前曾发送”——step1 时
   `history_sent` 为空，**step1 不可能满足 V3**，故“两步均省略”不可实现；
2. [已执行-只读代码核对] step1 是否会发送 stable 文件：`p1_common.assemble_vam_coder`
   中 `reuse_mismatch = history_sent.get(sid) != source_hash`，空历史下恒为
   True → 文件纳入上下文（回退展开）；且 step1 路由为 valid+kv_ptr→REUSE_KV
   （预算 4096 远大于玩具仓库）。**结论：step1 全量发送由既有回退语义保证**，
   无需也无法在不改代码的情况下“强制发送”（也**不允许**为凑任务通过而新增
   强制逻辑）；
3. 该结论是**对现有装配代码的静态推演，未通过运行验证**。

**改动**：
1. step1 预期：三文件全部纳入；`reuse_decisions≥2` 允许但
   `verified_safe_omission=false`（期望省略=0）；
2. step2 预期：stable_a/stable_b 各 1 次（Q3b 检查点=step2，期望≥2）；
3. 写明触发链前提：模型 step1 只改 hot.py——若模型改了 stable 文件则 V2
   失败，属指令遵循问题，走 Q3b 诊断 (i)，不得改判据；
4. IRR01/DEL01 同步补 step1 省略恒为 0 的说明（同一 V3 逻辑）。

**待验证 [待验证]**：资格测试中 step1/step2 的 assemble_audit 实际输出；
回退分支在真实 run 中的行为。
