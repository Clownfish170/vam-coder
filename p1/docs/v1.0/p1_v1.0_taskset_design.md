## 0. 能力边界（不可违反）

- `REUSE_KV` 是**文本上下文省略代理**：仅当符号当前内容哈希与对话中已发送内容一致时，才从提示词省略。**不是**真实 KV tensor 复用；不主张真实 KV cache 加速或显存收益。
- 服务端 `cached_tokens`（若返回）原样保存、单独解释，不等于 VAM 记忆仓命中。
- token 三分（API `prompt_tokens` / router `est_tokens` / chars-4 估算）不得混用。

## 1. 研究问题与假设（预注册）

**RQ1（主）**：在多轮 Python 代码维护任务上，`vam_coder` 相对 `memory_off`，
能否在 episode 成功率不明显下降的同时，降低累计输入 prompt tokens？

**RQ2（机制）**：版本感知失效（stale/unverified/tombstone → EXPAND/DROP）
是否在“过期记忆会致错”的任务上带来成功率差异（对照 `fixed_summary` /
`refreshed_summary`）？

**RQ3（成本结构）**：系统开销（sync+route+assemble）相对模型请求耗时的占比；
token 变化与端到端延迟变化是否同向（预答：**不一定**，禁止把 token 下降
解释为延迟或显存收益）。

联合主指标（RQ1）：每方法报告（episode 成功率，累计 prompt tokens）二元组；
结论必须同时引用两者。

## 2. 五组基线定义（与 v0.2 协议一致，补充可读性边界）

| 基线 | 可读取 | 同步 | 版本失效 | 摘要刷新 | 路由 |
| --- | --- | --- | --- | --- | --- |
| `memory_off` | 工作区全部当前 `.py` | 无（无 store） | 否 | 否 | 否 |
| `symbol_full_read` | 索引内全部存活符号所在文件全文 | 每步 sync | 检测但**不用于装配** | 否 | 否 |
| `fixed_summary` | 仅 episode 开始冻结的摘要 | 仅初始 sync | 否（永不失效） | 否 | 否 |
| `vam_coder` | 按决策：EXPAND=全文件 / COMPRESS=摘要 / REUSE_KV=哈希命中省略 / DROP=丢弃 | 每步 sync | 是 | 摘要随 sync 更新但仅 COMPRESS 时使用 | 是 |
| `refreshed_summary` | 每步刷新的摘要（无源码） | 每步 sync | 检测但**不门控**（tombstone 除外） | 是 | 否 |

**“无持久记忆”≠“无对话历史”——历史策略对比与推荐（C1）**

| 维度 | 策略 A（保留全部轮次，**推荐为主策略**） | 策略 B（assistant 代码块脱敏） |
| --- | --- | --- |
| 保留 | system；episode 内全部 user；全部 assistant（含失败/NO_EDIT/HTTP 错误的原文） | system；全部 user 原文；assistant 中 FILE 围栏块替换为 `FILE: <path> [redacted, N chars]`，其余文本保留 |
| 排除 | 预算内不排除任何消息 | 不排除消息，仅改写 assistant 代码内容 |
| 截断 | 估计字符数 > `max_history_chars`（24000）时，从最旧完整 (user, assistant) 对开始成对丢弃；system 与当前 user 永不截断 | 同一函数、同一预算、同一丢弃顺序（对**脱敏后**文本计量） |
| 失败响应 | 原文进入历史并占用预算（诚实记录；HTTP 失败时 assistant 轮为错误占位文本） | 同 A；失败文本无 FILE 块，天然短 |
| 实现状态 | v0.2 已实现（`trim_history`，四基线同一函数） | 未实现（列入实现清单 P1 项） |
| 优点 | 真实 agent 循环；零变换；与 v0.2 数据可比 | 源码唯一通道=装配上下文，机制归因干净 |
| 缺点 | assistant 历史含先前完整源码：摘要类基线可从**自己**的历史补回源码；历史 token 随步数增长，稀释方法间 token 差异 | 非真实（真实系统通常保留历史）；脱敏本身是变换，可能影响 1.5B 的格式遵循 |

**历史策略 × 研究问题的绑定（R1；取代 rev2 的“B 仅作可选敏感性”）**

同一**实验条件**内，五组基线必须使用**完全相同**的历史策略、预算与截断
规则（同一 `trim_history` 函数）。定义两个条件：

| 条件 | 历史策略 | 任务范围 | 承载的 RQ | 分析地位 |
| --- | --- | --- | --- | --- |
| **条件 A**（真实多轮） | 策略 A：保留全部 assistant 轮次（含失败/NO_EDIT 原文） | 全部 24 个任务 | **RQ1（成功率×token 联合）、RQ3（成本结构）** | 主分析 |
| **条件 M**（机制验证） | 策略 B/脱敏：assistant 的 FILE 围栏块替换为 `FILE: <path> [redacted, N chars]`；user 与 system 原文；同一预算截断 | **STM01、STM02、RFS01、RFS02**（4 个）；STM03 不进条件 M（探索性，见 §5.8） | **RQ2（过期摘要 / 摘要刷新的机制效应）** | 主分析（RQ2 专用） |

对三个方法的信息可获得性影响（条件 A 下，静态分析）：
- `fixed_summary` / `refreshed_summary`：装配上下文只有摘要，但 assistant
  历史包含其**自己**在 step1 写出的完整源码 → 实际可获得源码信息，摘要
  “饥饿”被历史部分补偿；
- `vam_coder`：历史同样含其 step1 展开的源码 → REUSE_KV 省略的相对收益
  被历史稀释（省略掉的内容可能已在历史里）；
- `memory_off` / `symbol_full_read`：本就重发源码，历史叠加只是 token 膨胀。
净偏置方向**未知**，不得预设偏袒某方法。

**解释纪律**：
1. 条件 A 的 STM/RFS 结果**不得**解释为干净的 stale-summary 因果效应
   （自身历史污染）；只作为“真实多轮场景下的描述性结果”报告；
2. RQ2 的主结论只来自条件 M（脱敏后，源码唯一通道=装配上下文）；
3. 条件 M 与条件 A 的任务子集差异对照属探索性，不替换各自主分析；
4. 跨条件不得合并样本、不得做联合显著性检验。

## 3A. 「已验证安全省略」的可审计定义（C5）

背景：rev1 仅以 `reuse_omitted` 描述“可安全复用”，但该字段只统计
“哈希命中且整文件未展开”的符号数，未记录“此前是否真发送过”“哈希是否
全文件一致”“本步是否真省略”，不可独立审计。

**判定谓词（R2：V1–V5 合取，唯一口径）**：文件 F 在步 t 构成一次
**已验证安全省略（verified safe omission）**，记 `O(F,t) = true`，当且仅当：

```
O(F,t) = V1 ∧ V2 ∧ V3 ∧ V4 ∧ V5
```

| # | 条件（判定用，参与合取） | 落盘字段 |
| --- | --- | --- |
| V1 | F 内至少一个非 DROP 符号的路由决策为 REUSE_KV（非 vam 基线无路由 → 恒 false，不参与省略统计） | `file_audit.decisions[]`（含 action） |
| V2 | 装配前，F 内**每个**非 DROP 符号 `history_sent[sid] == 当前 source_hash` | `file_audit.hash_match_all: bool` |
| V3 | F 在**本步之前**的上下文中曾以完整源码出现（`history_sent` 中已有记录） | `file_audit.previously_sent: bool` |
| V4 | 本步上下文未包含 F 的任何 FILE 块（实际省略发生） | `file_audit.included == false` |
| V5 | F 内容字节数 > 0 | `file_audit.omitted_bytes: int` |

**报告字段（不参与判定）**：
- `file_audit.omitted_tokens_est = omitted_bytes // chars_per_token` ——
  **仅估算**，字段名必须带 `_est`；`O=false` 时必须为 0；
- `per_step.csv.n_verified_safe_omissions = Σ 1[O(F,t)=true]`（**只按
  V1∧V2∧V3∧V4∧V5 计数**，与谓词严格一致——修复 rev2 中表含 V6、计数用
  V1–V5 的口径分裂）；
- `reuse_decisions`（决策级）与 `reuse_omitted`（v0.2 旧符号级计数）
  保留为兼容列，**不得**用于省略机制判定。

落盘要求：`result.json.assemble_audit = [{file, decisions:[{symbol_id, action,
history_match, previously_sent}], hash_match_all, previously_sent, included,
omitted_bytes, omitted_tokens_est, verified_safe_omission}, …]`，覆盖本步
出现过的全部非 DROP 符号文件（含 `included=true` 的，便于反向审计）。

**统一验收标准（设计草案 = 实现清单 = schema = 测试，四处一致）**：
1. 单测三样例：(a) V1–V5 全真 → 谓词 true、计数 +1、`omitted_tokens_est>0`；
   (b) 同文件有 EXPAND（V4 失败）→ false 且 `omitted_bytes=omitted_tokens_est=0`；
   (c) 未曾发送（V3 失败，如 step1）→ false 且 `omitted_bytes=0`；
2. schema 增补 `assemble_audit` 节时按本表逐字段写；
3. 完整性检查器校验
   `n_verified_safe_omissions == count(assemble_audit.verified_safe_omission)`；
4. 资格报告 Q3b 直接读 `verified_safe_omission` 谓词结果。

**硬性解释规则**：
1. 决策级 `reuse_decisions` **不是** token 节省；
2. `omitted_bytes` / `omitted_tokens_est` **不是**真实 token 节省，任何表
   标题不得写 “saved tokens”；
3. 真实 token 收益只能来自**跨方法比较**同一任务/步的 API `prompt_tokens`
   （并同时报告 `history_tokens_est`，见 §2 条件 A 的稀释效应）；
4. REUSE_KV 在所有输出中必须标注为文本省略代理，非真实 KV 复用。


## 4. 任务规范模板（每个 episode 必填）

```
ID / 类别 / 难度 / 检验的 RQ
初始文件树（含每文件要点）
step1 指令（原文，将逐字冻结）
step2 指令（原文）
step 依赖（step2 如何建立在 step1 之上）
预期代码修改（行为层面，非具体 diff）
隐藏测试（行为断言列表；禁止依赖 docstring/注释/格式）
成功判据（该 step 全部测试通过；无额外人工判据）
预期失效事件（sync 后应出现的 stale/unverified/tombstone）
预期路由行为（vam_coder：哪些符号应 EXPAND/DROP/可 REUSE）
非目标失败（易混淆的错误方式；计入失败分类而非成功）
如何检验研究假设（与 RQ 的映射）
```

### 5.9 摘要刷新对照友好（RFS）

设计意图：给 `refreshed_summary` 一个公平的获胜场景——任务所需的权威信息
在 docstring 摘要可传达的范围内（函数名+docstring 语义），而非隐藏在函数体
常量里。用于分离“摘要过期”（fixed 输）与“摘要信息量不足”（refreshed 也输）。

#### P1V1-RFS01 · M · RQ2
- 文件：`mode.py`（`def describe(): """Return the active mode name."""； return "idle"`）；`app.py`（`from mode import describe`；`def banner(): return f"mode={describe()}"`）
- step1：「当前模式应为 active。请修改 mode.py 的返回值，并同步 docstring 中的模式名描述。」
- step2：「app.py 新增 is_active()：当模式为 active 时返回 True（可基于 describe() 或当前语义）。」
- 摘要可传达性：docstring 含模式名 → refreshed step2 摘要含 “active”；fixed 冻结在 “idle”
- eval：`describe()=='active'`；`banner()=='mode=active'`；`is_active() is True`
- 失效：describe stale；banner unverified
- 路由：vam EXPAND；refreshed 无源码但摘要新
- 非目标失败：is_active 恒 True 忽略 describe（eval 增加：把 describe 改回的路径不可测——保持单向即可）
- 假设映射：**预期 refreshed_summary ≥ fixed_summary**（公平给对照组机会）；vam 应不劣于 refreshed 且 token 更多或相当——如实报告

#### P1V1-RFS02 · M · RQ2
- 文件：`status.py`（`def code(): """HTTP-ish code: 200 OK."""； return 200`）；`client.py`（`from status import code`；`def ok(): return code() == 200`）
- step1：「状态码应为 404。请修改 code() 返回值并同步 docstring 描述。」
- step2：「client.py 新增 is_missing()：状态码为 404 时返回 True。」
- eval：`code()==404`；`ok() is False`；`is_missing() is True`
- 假设映射：同 RFS01；与 STM 组对照解释“摘要内容类型”对结果的调节

## 7. 防偏差规则（预注册，任务 五）

1. **先冻结后运行**：24 任务 + eval + 参考补丁自检全部通过 → 生成
   `p1_v1.0_manifest_<date>.json`（不可覆盖）→ git tag `p1-v1.0-freeze` →
   才允许正式 run。资格测试在冻结前完成；冻结后改任何字节 = 新版本号 + 新清单。
2. **同条件**：同 episode 五组基线使用同一 project 拷贝、同一指令文本、
   同一模型参数（temperature=0, seed=0, max_tokens=1024, budget=4096,
   max_history_chars=24000）、同一 eval；独立 workspace/store/logs（已实现）。

4. **失败全保留**：任何 run/step 失败写入原目录；禁止删除、覆盖、重跑替换
   （重跑只能新增 rep/run_id）。
5. **难度标记先于结果**：CAP / TRIVIAL 标签只允许由**资格测试**（五组各一次）
   按第 8 节机械规则打上；正式实验结果**不得**用于增删任务或改标签规则。
6. **分析者盲态可选增强**：统计脚本先按 baseline 代号聚合、出表后再映射名称

## 8. 资格测试协议与剔除标准（任务 六）

**目的**：检查任务有效性（歧义、评测错误、机制未触发、基础设施故障），
**不用于**挑选 vam_coder 表现好的任务。

**流程**：冻结候选 → 五组基线各 1 次（24×5=120 episode-runs，rep 序号 Q=0，
独立 run 目录 `…_qual/`）→ 机械判定。

**预注册判定规则**（按序应用：Q1→Q2→Q3a→Q3b→Q4→Q5→Q6；每任务得到一个标签）：

| 规则 | 条件（机械可查） | 动作 |
| --- | --- | --- |
| Q1 评测错误 | 另行执行的参考补丁自检：补丁后 eval 不过；或初始仓库 eval 通过 | **EXCLUDE-设计**：修 eval → 升版本 → 重做资格测试；旧 qual 记录留档 |
| Q2 基础设施故障 | 五组中 ≥4 组同 step 出现 `MODEL_HTTP_ERROR`/`HARNESS_ERROR`/eval timeout | **EXCLUDE-设施**：修复后重跑该任务资格测试；留档 |
| Q3a 机制未触发（失效类） | 任务预声明表中该任务**全部 `required=true` 的 invalidation 条目**（按 step 绑定、按目标符号匹配）在 vam 的 invalidation JSONL 对应步增量中**合取成立**——**任一必需事件缺失即失败**；辅助事件（required=false）只记录不门控 | 必需事件缺失 → 先 **REVIEW** 三分诊断（同 Q3b：模型违例 / 实现缺陷 / 规格不可达），确认为规格-机制错配 → **EXCLUDE-设计**，升版本重测；留档 |
| Q3b 机制未触发（安全省略类） | 任务**预声明**省略（MECH-OMIT）：vam 在声明 step 的 `n_verified_safe_omissions` < 声明期望数（谓词见 §3A）。**仅适用于声明省略的 RUR02/IRR01/DEL01，不套用到其他任务** | 先 **REVIEW**：三分诊断——(i) 模型改了本不该改的文件（指令遵循失败，记 NOTE_INS_VIOL 线索，任务保留并标注）；(ii) 装配/审计实现缺陷（修实现→重测资格）；(iii) 规格使机制在设计上不可能（如 V3 不可达）→ **EXCLUDE-设计**，升版本重测。**任何情形下都不得因「五组全过」改判 TRIVIAL** |
| Q4 指令歧义（保守代理） | step1 五组全部 `MODEL_NO_EDIT` 或全部 `APPLY_REJECTED`，且该步标记难度 E | **REVIEW**：人工读 response 判定歧义；确认歧义 → 新版本改指令；不确认 → 保留并标注 |
| Q5 模型能力上限 | 五组在 step1 全部 eval 失败（任意原因，排除 Q1/Q2） | **CAP** 标签：保留进正式实验，分析时单独分层；不得删除 |
| Q6 区分度过低 | 五组 step1+step2 全部通过，**且**（任务声明省略 → Q3b 已通过；任务未声明省略 → vam `n_verified_safe_omissions` 两步均为 0） | **TRIVIAL** 标签：保留（提供“全过”地板与 token 对照）；不删除。**Q3b 失败的任务禁止落入本条** |
| 其余 | — | **OK**：进入正式实验 |

**预声明条目 schema（S6；机器可读，随清单冻结并做哈希校验）**

```
{ "task_id": "v1_cfd01", "step": "step2",        # step1 | step2
  "kind": "invalidation",                        # invalidation | omission | absence
  "event": "content_stale",                      # 见事件词表
  "target_file": "tax.py", "target_symbol": "tax_rate",   # 绑定初始仓库符号
  "role": "provider",                            # 人类可读，不参与匹配
  "required": true }                             # true=必需（门控） / false=辅助（记录）
```

- **事件词表**：invalidation ∈ {`content_stale`, `dependent_unverified`,
  `tombstone`, `insert`}；omission ∈ {`safe_omission`}（配 `min_count`）；
  absence ∈ 上述任一（声明“不应出现”）。
- **目标绑定**：`target_file` + `target_symbol` 必须是**初始仓库**中已存在的
  符号（P0 qualified_name 的 `::` 后段）；**模型新建符号不得作为必需目标**
  （新建符号的事件最多为辅助）。
- **匹配规则**：事件类型相等 ∧ 文件路径相等（posix）∧ 符号名相等。
  按步切片：取该步 sync 在 invalidation JSONL 中的增量（以 `sync_completed`
  为边界），只在该步增量内匹配。
- **Q3a 通过语义（合取，无“任一命中即过”）**：
  `Q3a_pass(task) = AND_{e ∈ required(task, kind=invalidation)} match(e)`；
  required 集合为空的任务不适用 Q3a（表中标注“无必需”）。
- **Q3b 通过语义**：对 required omission 条目按声明 step 与 `min_count`
  检查 `n_verified_safe_omissions ≥ min_count`（§3A 谓词）。
- **表哈希**：检查器启动时对预声明表做规范化 JSON sha256，写入资格报告；
  与冻结报告记录不一致则**拒绝运行**；资格期间修改表 = 校验失败。
- **P0 粒度约束（S7，实现前静态证实）**：`content_stale` 仅当**符号源区间
  字节**变化时触发；只改模块级常量/符号区间外文本**不会**使函数 stale
  （Python AST 静态验证：改 `STANDARD=3→5` 时 `fee` 的行区间不变）。因此
  必需 stale 事件的目标函数必须在对应 step 指令中被要求修改**函数体/签名/
  位于符号区间内的 docstring**。CFD02/DUP02/STM03/RUR01 已按此修订（S7）。

## 9. 正式实验定义（任务 七）

- **双条件矩阵（R1）**：
  - **Block A（条件 A，主分析 RQ1/RQ3）**：24 episodes × 5 baselines × R=3 =
    **360 episode-runs**（720 次模型请求），历史策略=保留全部；
  - **Block M（条件 M，主分析 RQ2）**：**STM01、STM02、RFS01、RFS02** 共 4 个
    × 5 baselines × R=3 = **60 episode-runs**（120 次请求），历史策略=
    统一脱敏（assistant 的 FILE 块替换为占位符）；STM03 不进 Block M；
  - 合计 420 episode-runs / 840 请求。Block A 与 Block M 是**不同实验条件**，
    各自 run 目录与 `run_meta.history_policy` 必须显式区分
    （`keep` / `redact`），禁止混合汇总。

    性写入运行配置，中途不可改。

  检查（失效事件、省略谓词）不依赖脱敏；脱敏属于正式实验 Block M 的条件
  变量。（Block M 若需资格确认，只复用同任务在条件 A 的 Q 标签，不重复跑。）

  t_* 分列、eval 输出、decisions/invalidation JSONL。
- **报告指标**：episode 成功率（两步全过；先对 reps 平均得 0–1 分）、
  step 成功率（仅辅助）、累计/中位 prompt tokens、端到端延迟（中位/p95，

## 10. 分析计划（任务 八）

**主分析（RQ1）**：
1. 每方法：episode 成功率均值（对 3 reps 平均）与 95% episode-level
   bootstrap CI（10,000 次重采样，episode 为单元）；
2. 累计 prompt tokens：每 episode-run 总和 → 对 reps 平均 → 方法间比值
   （vam/memory_off）+ bootstrap CI；
3. 联合陈述模板：「vam 相对 memory_off：Δ成功率 = x（CI），token 比 = y（CI）」；
   预注册描述性非劣界：Δ成功率 ≥ −0.10 视为“未观察到明显成功率损失”
   （**描述性**；n=24 不做正式非劣效检验声明）。

**机制分析（RQ2，主分析=Block M 条件 M）**：
- **样本规模约束（S1）**：Block M 的**独立统计单元是任务，n=4**
  （STM01/STM02/RFS01/RFS02）；4×5×3=60 是 episode-runs，三个重复是
  同一任务的重复测量，**不得**当作 60 个或 12 个独立样本；
- **结论强度预注册**：Block M 以**机制验证与任务级描述性比较**为主——
  逐任务报告成功率、失败类型与方向；对 fixed vs refreshed vs vam 只报告
  方向与区间，**不以 Block M 单独支撑**“版本感知失效普遍优于摘要记忆”
  一类宽泛结论；显著性检验**不适用于 Block M**（n=4）；
- 若四任务方向不一致，**如实并列保留**，禁止事后剔除“不利任务”或只报
  有利子集；
- **主结论只来自 Block M**（脱敏历史；STM01/STM02/RFS01/RFS02）：源码唯一
  通道=装配上下文，fixed vs refreshed vs vam 的差异可读作机制效应；
- Block M 内：STM01/02 上 fixed 与 vam 的差 = “过期摘要 vs 失效重读”效应；
  RFS01/02 上 refreshed 与 fixed 的差 = “摘要新鲜度”效应；均为 episode 级
  聚合（对 3 reps 平均）+ bootstrap CI；
- **条件 A（Block A）中的同 4 任务结果仅作描述性/场景对照**：受自身历史
  污染，**禁止**写成 stale-summary 因果效应，禁止与 Block M 合并样本或
  联合检验（§2 解释纪律 1/4）；
- STM03：探索性附表（§5.8），两个条件都不进主效应；
- 若 Block M 方向与 Block A 描述性结果不一致，必须并列报告并归因于历史
  策略差异，不得只报其一。
- 所有 token 相关表必须并列 `history_tokens_est` 与 `context_tokens_est`
  （§2 条件 A：历史可能稀释方法间差异，方向未知）。

**成本结构（RQ3）**：系统开销中位数占端到端比例；t_model 与总 tokens 的
Spearman 相关（探索性）；cached_tokens 命中率单列。

**失败分类**：对每个失败 step 机械归类
`MODEL_NO_EDIT / MODEL_BAD_FORMAT / MODEL_WRONG_SEMANTICS / APPLY_REJECTED /
EVAL_FAIL / MODEL_HTTP_ERROR / HARNESS_ERROR / NOTE_INS_VIOL`（从
result.error + apply.json + eval_output 规则判定），报告各方法分布。
`NOTE_INS_VIOL`：违反指令约束（如禁止调用却调用、禁止改无关文件却改了）
但**行为测试仍通过**的步——计为通过，另打此标注用于解释“指令遵循 vs
行为正确”的分离（C8）；不得因 NOTE_INS_VIOL 调整成功判据。

**统计检验门槛**：仅当某指标在 episode 级配对样本上分布不过度离散且无
大量并列时，才做 Wilcoxon 符号秩（vam vs memory_off，双侧，α=0.05，
并报告效应量）；结果无论显著与否均报告。CAP 分层任务不进入主检验，
单独附表。

**禁止**：把 step 当独立样本；把 token 下降写成延迟/显存收益；只报告赢家
任务；隐去 TRIVIAL/CAP 标签。
